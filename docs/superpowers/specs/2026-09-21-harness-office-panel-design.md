# Harness Office 聊天入口接入设计

## 目标与范围

替换本地 Web 中的 Genspark 聊天面板，保留 GenOffice 编辑器。先在 Sheets 验证，再复用到 Docs 和 Slides。保留 Harness 多供应商能力；模型密钥仅在 Host。Office 编辑仍使用原生工具，不引入 MCP。

## 已核实的集成约束

Harness 的 client-web 通过 Host 提供的 boot graph 启动插件树，并非可直接导入的独立聊天组件。ui-chat 消费已记录的 Session 数据；ask_user_question 消费 userQuestions 服务且必须有实际 answerer。当前 NexusDesk profile 仅组合 dsh-base，聊天是自有事件投影，不能仅替换外观便称为原生 UI 集成。

## 方案选择

推荐在现有 Harness 运行时上组合官方 Web Host/Client 插件，提供专用 Office 嵌入入口；入口只呈现当前文档的会话、输入、模型选择与交互卡片。不另起一个没有 Office 工具的通用 Harness 实例。完整 Harness 工作台 iframe 会重复导航并可能暴露无关能力，不作为目标方案。复刻样式不能满足复用原生交互的要求，不采用。

## 数据与权限

Local Host 保持文件授权、编辑器注册、审批、工作副本与保存的权威来源。嵌入入口与父页只交换经过验证的 documentId、编辑器类型、工作表、选区及版本；不授予任意文件读写。提交时冻结选区，记录为模型可见上下文，避免用户后续点击改变本轮操作目标。

会话绑定文档和 Host 身份；刷新恢复持久化 Session，不凭空重放写入。切换文件切换绑定会话。断线时显示真实状态，未核实的写入保持待核实，不标记成未发送或自动重试。

## 用户交互

AI 先用中文说明目的、位置及影响，再通过 ask_user_question 发出有名称、有说明的选项，支持自定义回答。选择结果必须返回同一请求并进入会话记录。普通求和默认只读并直接回答；只有需要明确输出位置或改变文件时才提出选择。

方案选择不等于任意写入授权。具体修改必须仍与实际计划及审批标识绑定。审批卡必须展示经过校验的实际修改内容，可配合 AI 解释，但不能只信任模型声称的操作。工具名、哈希及原始 JSON 留在诊断详情，不作为主文案。

等待选择、已选择、执行中、成功、失败、结果未知分别呈现。通用问题等待用户回答或取消，不套用当前审批卡 110 秒超时。写入审批保留其安全时效；过期必须明确重新生成计划，不能让旧按钮恢复授权。旧的临时 DOM 审批卡不与原生入口重复渲染。

## 验收

1. Sheets 选区 C1:C3 含 1、2、3 时，原生会话调用读取工具获得逐格数据并回答 6，不写入文件。区域读取缺陷须先修复，避免新 UI 继续展示错误结果。
2. 明确要求写入合计时，中文解释与实际公式、位置一致；拒绝不修改，批准仅执行一次。
3. 问题选项及自定义回答能回到等待中的同一 Agent；没有 answerer 时显式报错。
4. 刷新、取消、断线及迟到事件不产生重复写入或无限等待。
5. 模型选择使用真实供应商配置；浏览器不包含密钥，不出现 Genspark 登录回退。
6. Docs、Slides 复用相同入口；各自文档与选区隔离。

## 当前状态

已完成源码接入调查及设计，尚未实现原生入口。正式编码前需要确认该架构设计，并进一步核对官方 Host 插件组合、嵌入布局扩展点及构建依赖，形成文件级实施计划。不能把临时卡片改名作为完成交付。
